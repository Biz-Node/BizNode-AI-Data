## 0. 다음 개발 순서

아래는 **주제별 우선순위 태그와 별개로**, 실제로 진행할 순서입니다. ①이 끝나야 ②를
의미 있게 검증할 수 있고, ③·④는 ①·②가 코드를 바꾸는 걸 알기 때문에 일부러 뒤로
미룹니다 — 먼저 해도 그 뒤에 또 해야 하면 두 번 일하는 것입니다.

```
① SEMANTIC 검색 결과 가중치 처리 (4절)
       │  RetrieveResponse에 match_type 노출 → AnswerService가 다르게 취급
       ▼
② /ask 답변 품질 최소 검증 (4절)
       │  ①이 실제로 프롬프트에 반영됐는지 확인하는 게 목적 — ① 없이는 의미 없음
       ▼
③ /ask 운영 이미지 기동 검증 (2절)
       │  ①·②가 answer_service.py/schemas.py를 바꾼다 — 최종 모양이 나온 뒤 한 번만
       ▼
④ 문서 정합성 정리 (2절)
       │  ①·②로 테스트 개수·동작 설명이 또 바뀐다 — 그 이후 한 번에
       ▼
⑤ timeout·N+1 실측 → anchor/EntityResolver → ranking 품질
   → prompt token 실측 → 모델/temperature 재검토 (5절·4절, ①~④와 직접 의존관계 없음)
```

## 4. LLM/프롬프트 품질 관련 검토 사항

`/ask`는 구조적 안전성(화이트리스트 검증·인젝션 방어·실패 구별)만 검증됐고, **답변의
내용 품질은 아직 아무도 채점한 적이 없습니다.** 이 절이 그 격차를 추적합니다.
★①·②는 [0절](#0-다음-개발-순서)의 첫 두 단계입니다 — 이 문서 전체에서 **가장 먼저** 진행합니다.

| 항목 | 상태 | 우선순위 | 왜 |
|---|---|---|---|
| **① SEMANTIC 결과 가중치** — 설계서 §11 "SEMANTIC 결과를 같은 무게로 말하지 않는다"를 시스템 프롬프트가 못 지킴 | `[TODO]` (결정 완료) | **최우선** | **결정: `RetrieveResponse`에 `match_type`(`EXACT`/`SEMANTIC`)을 노출한다.** 작업은 두 단계다 — (1) 데이터 흐름부터: Retrieve Layer는 이미 어떤 경로로 찾았는지 안다(`SearchQuery.mode`) — 이 값을 `RetrieveResponse`(또는 관련 엔드포인트)까지 흘려보낸다. (2) 그다음 `AnswerService`의 `_fact_lines`/시스템 프롬프트가 `match_type`을 보고 다르게 말하도록 반영한다. **②의 선행 작업** — 순서를 반대로 하면 검증할 데이터가 없다 |
| **② `/ask` 답변 품질 최소 검증** — 대표 질문으로 EXACT/SEMANTIC 근거가 의도대로 쓰이는지 확인 + 답변 내용을 사람이 직접 읽어봄 | `[TODO]` | **최우선** (① 완료 후) | ①이 실제로 프롬프트에 반영됐는지 보는 게 이 단계의 핵심 목적이라 ① 없이는 의미가 없다. 구조적 검증(환각·missing 인용 없음)은 이미 있으니, 여기서는 "EXACT/SEMANTIC을 답변이 정말 다르게 말하는가"와 전반적 자연스러움을 사람이 본다. 설계서 §13-5의 "LLM-judge 없음" 원칙은 유지 — 자동 채점기를 새로 만들지 않는다. Search Layer의 20케이스 회귀 평가셋([평가셋 문서](BizNode_Search_Layer_평가셋.md))과 짝을 이루는 절차가 아직 없다 |
| **모델/temperature 적합성** — `pipeline/llm.ask_json()`의 기본값(`gpt-4o-mini`, `temperature=0.0`)을 그대로 재사용 | `[MEASURE]` | 단기 | 이 기본값은 원래 **판정·분류·요약**(재현 가능해야 하는 배치 작업) 용도로 정해졌다. `/ask`는 자연어 **생성**이라 성격이 다르다 — "재사용하라"는 원칙(설계서 §12)과 "이 용도에 맞는가"는 별개 질문. 실사용 트래픽 없이 지금 바꾸면 근거 없는 변경이 된다 |
| **prompt token·context 크기** — `_fact_lines`/`_evidence_block`이 만드는 프롬프트 길이를 잰 적 없음 | `[MEASURE]` | 단기 | RetrieveService의 상한(`_MAX_COMPANIES=5`·`_MAX_RELATIONS_PER_COMPANY=10`·`_MAX_RISK_EVENTS_FOR_PROPAGATION=3`)은 **재료 개수용**으로 정해진 값이지 토큰 예산으로 정한 게 아니다 |
| **답변 형식/톤/길이 기준** — 시스템 프롬프트에 답변 규칙 6개만 있고 문단/목록·길이 상한·인용 밀도 지침이 없음 | `[DECIDE]` | 단기 | 엔지니어링 단독 결정 사안이 아니다 — 프로덕트/프론트 쪽과 "화면에 어떻게 보일지" 먼저 맞춰야 한다 |
| 인젝션 방어를 구조적 방어(델리미터+화이트리스트)로만 한정 | `[DEFER]` | — | 설계 단계에서 **의도적으로** 내린 트레이드오프(설계서 §13-2, "추가 LLM 호출 없음"). 결함이 아니라 결정 — 더 높은 신뢰 수준이 필요해지면 사전 탐지 LLM 호출이 다음 계층 후보 |
